# 需求摘要

## 业务闭环

市民报修或巡检发现问题后，系统完成问题分诊、设施识别、优先级/SLA 判断、巡检计划、工单派发、维修安全检查、结果验收和审计回填。

## Agent

1. 问题分诊 Agent：识别设施类型、问题类型和重复报修。
2. 设施识别 Agent：从位置和历史事件关联设施台账。
3. SLA Agent：根据设施类型、区域和风险判断响应时限。
4. 巡检计划 Agent：生成巡检任务和路线建议。
5. 工单调度 Agent：根据技能、区域、工作量和供应商能力推荐派工。
6. 安全作业 Agent：识别电气、道路和交通安全风险，必要时转人工确认。
7. 维修验收 Agent：检查处理说明、照片/证据和状态变更，生成验收结论。

## RAG 菜单

文档上传、文本切块预览、向量化入库、检索调试和原文片段查看必须有独立菜单。每个 Agent 都可以按设施类型、区域、版本和生效日期过滤后检索 Chroma。

## 数据原则

公开数据只承担历史事件和位置案例；设施台账、巡检、人员、供应商、SLA、工单、验收、Agent 运行和审计由 MySQL 业务表承载。高风险状态变更要求权限检查、幂等键和人工确认。
